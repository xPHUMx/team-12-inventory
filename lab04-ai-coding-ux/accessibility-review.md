# Accessibility Review (WCAG AA Checklist) - Lab 04

เอกสารตรวจสอบการออกแบบหน้าจอ UI ตามมาตรฐานการเข้าถึง (Accessibility) ระดับ WCAG 2.1 AA สำหรับหน้า Dashboard และ Add Product

## 1. ตารางตรวจสอบ Accessibility Checklist

| รายการตรวจ | ผ่าน หรือ ไม่ผ่าน | สิ่งที่ตรวจพบและสิ่งที่ปรับปรุงแก้ไข |
|---|---|---|
| **1. ข้อความหลักบนพื้นขาว contrast อย่างน้อย 4.5 ต่อ 1** | **ผ่าน** | ใช้สีข้อความหลักเป็น `#111827` (Dark Charcoal) บนพื้นหลังสีขาว `#FFFFFF` ได้ค่า Color Contrast Ratio สูงถึง **16.1:1** (สูงกว่าเกณฑ์ขั้นต่ำ 4.5:1) |
| **2. ปุ่มหลักมี contrast เพียงพอ** | **ผ่าน** | ปุ่มหลักใช้พื้นหลังสีน้ำเงิน `#1E40AF` ตัวอักษรสีขาว `#FFFFFF` ได้ Contrast Ratio **8.5:1** (ผ่านเกณฑ์ WCAG AA สำหรับ Graphical Objects และ Text) |
| **3. ทุกช่องกรอกมี label ที่มองเห็น** | **ผ่าน** | ทุก Input Field มี `<label>` วางอยู่ด้านบนชัดเจน ไม่ได้ใช้เพียงแค่ Placeholder ลอย ๆ ในช่อง ทำให้ผู้ใช้ไม่ลืมความหมายเมื่อกำลังพิมพ์ |
| **4. ช่องที่บังคับกรอกมีสัญลักษณ์ชัด** | **ผ่าน** | มีเครื่องหมายดอกจันสีแดง `*` กำกับที่ Label ทุกช่องที่จำเป็นต้องกรอก พร้อมระบุข้อความอธิบายในหัวฟอร์ม |
| **5. error ไม่ได้ใช้สีอย่างเดียว มีไอคอนหรือข้อความด้วย** | **ผ่าน** | ช่องที่มีข้อผิดพลาดใช้เส้นขอบสีแดง ควบคู่กับไอคอนเตือน `[!]` และข้อความบอกสาเหตุใต้ช่อง เช่น `[!] กรุณาระบุชื่อสินค้า (ห้ามเว้นว่าง)` ผู้มีภาวะตาบอดสีแดง-เขียวรับรู้ได้ทันที |
| **6. ลำดับการกด Tab เรียงบนลงล่าง ซ้ายไปขวา** | **ผ่าน** | จัดลำดับ DOM / TabIndex ต่อเนื่อง: เลือกชนิดสินค้า -> รหัส -> ชื่อ -> หมวดหมู่ -> ราคา -> จำนวน -> ปุ่มบันทึก |
| **7. ปุ่มมีชื่อบอกหน้าที่ ไม่ใช่ OK หรือกากบาท** | **ผ่าน** | ปุ่มระบุหน้าที่ชัดเจน เช่น `"บันทึกข้อมูลสินค้า (Enter)"`, `"ยกเลิก (Esc)"`, `"+ เพิ่มสินค้าใหม่"` ไม่ใช้คำกำกวมอย่าง `"OK"`, `"Submit"`, หรือไอคอนกากบาทลอย ๆ |

## 2. จุดบกพร่องที่ AI ทำพลาดและเราปรับปรุงแก้ไขเอง (อย่างน้อย 2 จุด ตามเกณฑ์ Rubric)

### 🔴 จุดที่ 1: การใช้ Placeholder แทน Visible Label และ Contrast สีเทาอ่อนเกินไป
- **สิ่งที่ AI สร้างมาในร่างแรก:** AI ออกแบบช่องกรอกรหัสและชื่อสินค้าโดยไม่มี `<label>` ด้านบน แต่ใส่ข้อความตัวอย่างสีเทาจาง (`#9CA3AF`) ไว้ใน Placeholder เท่านั้น เช่น `[ พิมพ์ชื่อสินค้าตรงนี้... ]`
- **ปัญหาที่พบ:** 
  1. เมื่อผู้ใช้เริ่มพิมพ์ตัวอักษรตัวแรก ข้อความ Placeholder จะหายไป ทำให้ผู้ใช้สับสนว่าช่องนี้คืออะไร
  2. สีเทา `#9CA3AF` บนพื้นขาวมี Contrast Ratio เพียง **2.5:1** (ไม่ผ่านเกณฑ์ WCAG AA 4.5:1) ผู้มีสายตาเลือนรางอ่านไม่ออก
- **สิ่งที่แก้ไข:** เพิ่ม Visible Label ขนาด 14px หนาปานกลางสี `#111827` ด้านบนทุกช่องกรอก และเปลี่ยนสีกรอบอินพุตให้มี Contrast ชัดเจน

### 🔴 จุดที่ 2: การแจ้งเตือนข้อผิดพลาดพึ่งพาสีแดงเพียงอย่างเดียว และข้อความไม่บอกวิธีแก้
- **สิ่งที่ AI สร้างมาในร่างแรก:** เมื่อกรอกข้อมูลไม่ครบ AI เปลี่ยนสีกรอบช่องเป็นสีแดง และขึ้นข้อความสั้น ๆ ว่า `Invalid input`
- **ปัญหาที่พบ:**
  1. ละเมิดเกณฑ์ WCAG SC 1.4.1 (Use of Color): คนตาบอดสีจะไม่ทราบว่าช่องไหนกรอกผิดเพราะแยกสีแดงกับเทาไม่ออก
  2. ละเมิดเกณฑ์ Usability: ข้อความ `Invalid input` ไม่ได้บอกว่าผู้ใช้ต้องทำอย่างไรต่อเพื่อแก้ไข
- **สิ่งที่แก้ไข:** เพิ่มไอคอนเครื่องหมายตกใจ `[!]` พร้อมระบุข้อความแนะนำการแก้ปัญหาอย่างเจาะจง เช่น `[!] กรุณาระบุชื่อสินค้า (ห้ามเว้นว่าง)` และ `[!] กรุณาตรวจสอบปุ่ม Caps Lock`
